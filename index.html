Git + GitHub

The GitHub Cheat Sheet for Vibe Coders

Version control has been around for over 50 years, but if you learned to build with AI, chances are nobody ever showed you how it works. This is the whole thing on one page, with the exact Claude prompts for saving your progress, undoing a broken change, and testing a feature safely.

How to use this: every box with a Copy button is a prompt. Copy it, paste it into Claude, and Claude runs the Git commands for you. You don't need to memorise a single command.

Why it works

GitHub runs on Git, a version control tool developers use to track changes. Git saves your project as a timeline of snapshots. GitHub keeps a copy of that timeline online. Claude already knows Git inside out, so you just tell it what you want in plain English and it handles the rest.

The basics

Seven words that explain all of Git

Everything in this guide comes down to these. Read them once and the prompts below will make sense.

  • CommitA snapshot of the files Git is tracking, linked to the snapshot before it. Commit by commit, that's your app's timeline.
  • PushUploads your commits to GitHub, so your history lives online. If your laptop dies, your project doesn't.
  • CloneThe other way around. Copies a project and its whole history from GitHub to your computer. It's how you grab AI tools from GitHub.
  • BranchA second timeline that splits off from the first, so you can try a new feature without risking the version that works.
  • MergeThe feature worked? Merge the branch back into your main timeline.
  • Delete a branchThe feature didn't work? Delete the branch. Your main version never knew it happened.
  • TagA name like v1 stuck on one exact commit, so you can find that version any time.
Do this once

Set up Git and GitHub

You need a free account at github.com. Then open your project in Claude Code and paste this:

Prompt Check if Git and the GitHub CLI are installed on my computer, and install them if they're not. Then walk me through logging in to GitHub. I'll do the login step myself.
Prompt Turn this project into a Git repository, make the first commit, then create a new private repo on my GitHub and push it there.

Private means only you can see it. Say "public" instead if you want to share the code.

1 · Save your progress

Commit and push. Every time something works.

If you remember one thing from this guide, make it this. Every time your app is in a good state, save it to your timeline and back it up online.

The one you'll use most Commit and push.
With a clear message Commit everything with a clear message describing what changed, then push to GitHub.
See your timeline Show me my last 10 commits in plain English: when each one was made and what it changed.
Make it automatic From now on in this project, commit and push every time a feature is working, with a short clear message. Add this rule to my CLAUDE.md file.

A commit only lives on your laptop. A push puts it on GitHub. You want both.

2 · Undo a broken change

One prompt broke your app? Go back.

This is why you commit. When something breaks, you don't have to fix it. You can rewind to the last commit that worked.

Step 1. Find the last good version

Prompt My app just broke. Show me my recent commits and help me figure out which one was the last version that worked.

Step 2. Go back to it

The safe rewind Take me back to the last commit that worked. Do it safely by making a new commit that undoes the broken changes, so nothing is lost from my history. Then push.

Other undo prompts

Broke it, haven't committed yet Throw away all the changes I've made since my last commit. First show me exactly which files will be reset and wait for me to say yes.
Undo just the last commit Undo my last commit safely with a new commit that reverses it, then push.
Just look, don't change anything Let me look at how my app was at commit [paste commit or describe it] without changing anything. Then bring me back to the latest version.

Notice the word "safely". It tells Claude to undo with a new commit (a "revert") instead of deleting history. You can always undo the undo.

3 · Test a feature safely

Make a branch. Merge it or delete it.

Want to try a new feature without risking the version that works? Split off a second timeline. Your working app stays untouched until you decide.

Step 1. Split off a new timeline

Prompt Commit my current work, then create a new branch called [feature-name] and switch to it. Build the feature on this branch only.

Step 2a. It worked? Merge it in

Prompt The feature works. Commit it, merge this branch into main, push to GitHub, then delete the feature branch.

Step 2b. It didn't work? Delete it

Prompt This feature didn't work out. Switch me back to main and delete the [feature-name] branch. Make sure main is exactly how it was before.
Lost track? Which branch am I on right now, and what other branches do I have?
Bonus · Tag and clone

Bookmark a version. Grab a tool.

Tag a version you want to come back to

Prompt Tag the current commit as v1 and push the tag to GitHub.
Prompt Show me my app exactly as it was at v1, without changing anything. Then take me back to the latest version.

Clone an AI tool from GitHub

Prompt Clone this repo: [paste GitHub link]. Then read its README and tell me in plain English what it does and how to run it.

Only clone and run code from people and projects you trust. Ask Claude to explain what a project does before you run it.
